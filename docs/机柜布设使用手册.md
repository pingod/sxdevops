# 机柜布设使用手册

「机柜布设」是单机柜内部的 U 位排布编辑器，从上游 [RackDraw](https://github.com/bruce609685-collab/RackDraw)（Apache-2.0）迁移而来，用 Vue 3 + SVG 重写。它负责“一个机柜里每台设备放在第几 U、横向占多宽”，不负责跨机柜布线，也不做机房几何建模。

## 与相邻功能的边界

| 入口 | 范围 | 数据 |
| --- | --- | --- |
| 机柜布设 | 单柜内部 U 位/孔位布局，1/2、1/3 宽并排，布设表与图片导出 | 平台机柜布设方案库（覆盖保存 + 版本/乐观锁） |
| IDC 上架布线 | 项目级多机柜上架、布线表、线长、耗材与 IP 规划 | vendored `planning` 子系统数据库 |
| 三维机房设计 / 数字孪生 | 机房几何、构件与三维呈现 | 平台机房项目库 |

职责区分：

- 需要“某台交换机在 A01 柜第 42U、占半宽”时，用机柜布设。
- 需要“从 A01 到 B12 的跳线长度、端口对应、耗材清单”时，用 IDC 上架布线。
- 需要“机房长宽、通道、立柱、空调位置”时，用三维机房设计。

机柜布设目前**不计算线缆长度、不做 IP 规划、不自动生成采购量**，也不替代 IDC 布线表。

## 入口与权限

- 菜单：`数据中心 → 机柜布设`。
- 路由：`/datacenter/rack`。
- 权限：
  - `datacenter.rack.view`：查看方案列表、内容与版本历史。
  - `datacenter.rack.manage`：新建、保存、另存为、改名、删除与回滚。
- 菜单显示还受「系统管理 → 模块可见性」的 `datacenter.rack` 模块开关控制。

后端在 API 层强制校验权限，前端按钮隐藏只是镜像；只读账号即使直接调用写接口也会被拒绝。

## 页面结构

- 顶部统计：方案数、当前设备数、已用 U 数、空间利用率。
- 提示条：当前对齐方式（U 对齐 / 孔位精调）与未保存状态。
- 工具栏：方案选择、新建、保存、另存为、方案信息、版本、删除、导入/导出布设、导出图片、机柜规格、柜宽、对齐方式、缩放。
- 左侧设备目录：按类别分组，支持搜索与自定义设备。
- 中间机柜画布：拖放设备、选中、移动，显示 U 号与孔位。
- 右侧设备属性：名称、类别、宽度、高度、顶边 U 位、横向位置、资产编号、序列号、负责人、备注。

## 基本操作

### 新建与保存

1. 点击「新建」，填写方案名称（全局唯一，忽略大小写），选择机柜规格（42U / 36U / 24U）与柜宽（600 / 800 / 1000mm）。
2. 从左侧目录点击设备，自动放入自顶向下的第一个可用格位；也可以拖到画布上的目标位置。
3. 选中设备后可在右侧属性面板修改名称、类别、宽度、高度、横向位置与顶边 U 位。
4. 点击「保存」写入平台方案库；`Ctrl/⌘ + S` 同效。
5. 「另存为」以当前内容创建新方案，不影响原方案。

### 上架与移动

- 点击目录项：按当前对齐方式寻找第一个可用格位。
- 拖拽目录项到画布：绿色预览表示可放置，红色表示冲突；松手后吸附到最近的合法格位。
- 拖动已上架设备：同样按格位吸附，不会与其它设备重叠。
- 选中设备后：
  - `↑` / `↓`：移动 1 个孔位（U 对齐模式下为 1U）。
  - `←` / `→`：移动 1 个横向格位。
  - `Delete` / `Backspace`：移除设备。
  - 「复制到空位」：保留属性，放到下一个可用格位。

### 对齐方式

- **U 对齐**：设备顶边只落在整 U 边界，适合常规上架。
- **孔位精调**：设备可停在 1/3U 的螺丝孔位上，适合需要精确对孔的场合。

切换对齐方式时，已有设备会重新吸附；切换机柜规格会重新排布，放不下的设备会被移除，操作前会二次确认。

### 自定义设备

「我的设备 → 新建自定义设备」可登记名称、宽度（全宽 / 1/2 / 1/3）与高度（1–24U）。自定义设备保存在当前方案内，随方案内容一起入库；删除后不影响已上架实例。

### 版本、乐观锁与回滚

- 每次保存都会把内容版本号 +1；保存请求必须携带 `base_version`。
- 若他人已先保存，服务端返回 409，页面提示当前版本与最后修改人，可选择：
  - 加载最新内容（丢弃本地未保存修改）。
  - 另存为副本（保留本地内容）。
- 内容发生变化时，保存前会为旧版本留快照；最多保留最近 30 个版本。
- 「版本」对话框可查看版本列表并回滚；回滚会先把当前内容留快照，再把目标版本写为新版本。

### 导入与导出

- **导出布设**：生成 Markdown 布设表，包含基本信息、设备清单（按 U 位自下而上）、U 位占用对照图、空间统计与分类统计。
- **导出图片**：把当前机柜画布渲染为 PNG（2 倍分辨率），样式随 SVG 内联，脱离页面也能正确显示。
- **导入布设**：读取 RackDraw 兼容的 Markdown 布设表。导入会：
  - 从「机柜规格」「卡位版式」还原机柜与对齐方式；
  - 按「U 位」「横向位置」「设备名称」「宽度」「高度」「顶边孔位」解析设备；
  - 名称能匹配目录的沿用类别，匹配不到的按自定义设备导入；
  - 目标格位被占用时向下寻找最近空位，找不到则跳过并写入报告；
  - 只还原布局与名称，不还原资产编号、序列号、负责人、备注与 CMDB 关联。
- 导入前会保留一份当前内容用于「撤销导入」。

## 数据口径

- 机柜横向 6 等分，设备宽度只允许 6（全宽）、3（1/2 宽）、2（1/3 宽）。
- 纵向每 U 3 个螺丝孔位；设备只存顶边孔位 `hole`，U 号由孔位推导：
  `U = 机柜总 U 数 - floor(hole / 3)`。
- 同一格位不允许重叠；前后端都会校验，外部脚本写入重叠数据会被拒绝。
- 内容上限：单方案最多 300 台设备、500 个自定义设备，内容大小不超过 4MB。
- 设备名称最长 60 字，备注最长 500 字，方案名称最长 120 字，描述最长 255 字。

## 接口与审计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/datacenter/rack/projects/` | 方案列表（分页，支持搜索与排序） |
| POST | `/api/datacenter/rack/projects/` | 新建方案 |
| GET | `/api/datacenter/rack/projects/{id}/content/` | 读取原始布设 JSON |
| PUT | `/api/datacenter/rack/projects/{id}/` | 覆盖保存（必须带 `base_version`） |
| PATCH | `/api/datacenter/rack/projects/{id}/` | 只改名称/描述，不升版本 |
| DELETE | `/api/datacenter/rack/projects/{id}/` | 删除方案 |
| GET | `/api/datacenter/rack/projects/{id}/versions/` | 版本快照列表 |
| GET | `/api/datacenter/rack/projects/{id}/versions/{v}/content/` | 指定版本内容 |
| POST | `/api/datacenter/rack/projects/{id}/rollback/` | 回滚到指定版本 |

新建、保存、改名、删除与回滚都会写入事件中心，资源类型为 `rack_project`，可直接按方案名检索操作记录。

## 常见问题

- **保存提示版本冲突**：说明其他人先保存了。先加载最新确认差异，或把本地内容另存为副本，不要反复重试覆盖。
- **导入后设备位置变了**：目标格位可能被占用，导入会向下顺延；报告里会列出“位置调整”与“跳过”项。
- **导入后设备变成“自定义”**：导出的设备名被手工改过，无法匹配目录中的标准名称；这是预期行为，可在属性面板改回目录设备。
- **切换机柜规格后设备变少**：低 U 数机柜放不下的设备会被移除；请先导出布设表留档。
- **图片导出空白或文字缺失**：确认浏览器允许下载；导出样式随 SVG 内联，不依赖页面主题。

## 验证与已知边界

- 后端：`tools/run_backend_tests.sh datacenter`，覆盖权限、几何校验、重叠拒绝、乐观锁、快照、回滚、搜索排序与 404 场景。
- 前端：`npm run build` 通过；已用浏览器实测新建、点击/拖拽上架、属性改名、保存、刷新回读、版本列表、Markdown/PNG 导出、Markdown 导入与删除。
- 已知边界：
  - 布设表导入不保留资产字段与 CMDB 关联。
  - 不计算线缆长度、不生成布线表，也不做跨机柜规划。
  - 上游 RackDraw 为 Windows 桌面程序，本项目只迁移其数据口径与交互，不包含其原生导出器。

# 数据中心设计与数字孪生

本文说明左侧菜单 `数据中心` 下三个入口的分工、数据流和运维要求。目标是避免把「数字孪生」「平台项目设计」「本地 CAD 工作台」混用。

## 入口与定位

| 入口 | 定位 | 数据 | 典型场景 |
| --- | --- | --- | --- |
| 数字孪生 | 只读三维呈现与实时状态 | 平台项目库 | 汇报、巡检、运行状态查看 |
| 三维机房设计 | 平台项目编辑器（CAD 内核，含 AI 建模） | 平台项目库 + 版本/乐观锁 | 新建/修改机房并保存到项目库 |
| 独立工作台（编辑器工具栏） | 本地/离线 CAD | 本地 JSON | 工勘、批量建模、DXF/CSV 导入导出 |

`IDC 上架布线` 是独立的机柜上架与布线规划子系统，不用于机房几何建模。

## 三维机房设计（平台项目模式）

平台页面 `DatacenterTwinDesign.vue` 通过 iframe 加载 `/dc-designer-app/?embed=1&lang=zh-CN`，保留原有项目库能力：

- 项目列表、搜索、分页、版本历史和回滚。
- 保存使用 `base_version` 乐观锁；冲突时选择加载最新或另存为副本。
- 权限：`datacenter.twin.manage`；只读查看孪生使用 `datacenter.twin.view`。

编辑器与平台通过 postMessage 握手：

| 方向 | 消息 |
| --- | --- |
| 设计器 → 平台 | `ready` / `dirty` / `save` / `error` / `ai-chat` |
| 平台 → 设计器 | `load` / `new-room` / `request-save` / `saved` / `cancel` / `error` |
| 平台 → 设计器 | `ai-chat-result`（模型代理回传） |

平台模式会隐藏设计器自带的本地文件组和工勘向导；`Ctrl+S` 走平台保存。项目库、版本、RBAC 与审计由平台负责，编辑器只持有当前画布数据。

AI 建模也在平台模式内：设计器的 `ai-chat` 请求由本页带登录态转发到 `/api/aiops/modeling/chat/`，服务端选择 AIOps 默认模型提供商并写审计。详见[AI 机房建模](AIOps-AI机房建模.md)。

## 独立工作台

编辑器工具栏的「独立工作台」在新窗口打开 `/dc-designer-app/`，用于：

- 现场工勘、离线编辑，本地 JSON 打开/保存。
- 16 类构件、合规检查、PNG/DXF/CSV 导出。
- 3D 检视（巡检/步行/剖切/定位/显示/拆解）。
- AI 机房建模（`?ai=1`，使用本机配置的模型）。

独立模式不写平台项目库，也不复用平台登录态；需要进入项目库时回到 `三维机房设计`。

## 数据与兼容

项目 JSON 为 `{name, meta, objects[]}`，对象单位为毫米，原点为房间西南内角，X 东、Y 北。平台项目库与 CAD 编辑器使用同一格式；`tools/dc-designer/public/fixtures/` 提供 demo、pipes、all-types 三个样例。

## 部署与排障

- 镜像构建包含 `tools/dc-designer`，产物由 Django 静态视图 `/dc-designer-app/` 托管；需同时构建 `tools/dc-viewer` 作为检视子应用。
- 页面提示“机房设计器未构建”时，确认镜像构建阶段 `dc-designer-builder` 成功，且 `tools/dc-designer/dist/index.html` 存在。
- 编辑器的本地文件组被隐藏、工勘向导不显示，是平台模式的预期行为，不是缺陷。
- 版本冲突不要强制覆盖；按页面提示加载最新或另存为。

## 验证

- 前端生产构建通过。
- 设计器单测、e2e（向导→POD→检查→导出→3D→检视）通过。
- 平台页实测：新建机房、加载项目、脏标记、保存对话框、项目库版本路径可用。

# IDC 上架布线 · 真实数据复用评估

> 评估对象：`~/githome/IDCBoxLine/信息港部署上架`（甘肃信息港 / 丝绸之路信创云真实交付物）。
> 评估问题：① 当前 IDC 上架布线功能能否复用这套数据；② 产品能否满足这些数据的使用场景；③ 能否自动生成这些数据。
> 结论日期：2026-11-15。所有数字均来自运行引擎实测与引擎反解报告，非估算。

## 0. 一句话结论

**这不是「能否复用」的问题——当前 IDC 上架布线引擎（vendored IDCBoxLine，MPL-2.0）本身就是按这套数据反解开发的，运行中的引擎现在就加载着 V13 信息港数据。** 复用已成立且往返保真；核心上架布线场景全满足；自动生成覆盖约 89%，剩余部分有明确的诚实边界。

## 2. 问题①：复用 —— 能，且已在跑

- **同源**：仓库已 vendoring 这套数据；引擎种子库 `planning/data/idcbox.db` 即「V13 / 信息港二期」。
- **运行实测**（容器内直查 `/api/meta`）：`projectLabel=V13(内部)甘肃信息港-设备上架规划-20260714`，**5127 有效行、362 柜位（403/404 两房）、834 台归一化设备、5127 条连线全部算通、0 错误行**。

- **导出铁线**：`domain/exporting/contract25.py` + `scripts/verify_export.py`，24 列 × 5127 行 = **123072 格与客户原表逐格比对，差异 0 格**。任何时刻非 0 即引入真 bug。这是往返保真的最强证明。
- **跨版本对比**：`domain/exporting/stockdiff.py` 支持 V3/V8/V9/V11/V12/V13 任意两版互比；实测五版「连线表(不含长度)」按前 11 列取键逐行相同（共有 5110，左右各 0）。

**诚实边界**（`planning/AGENTS.md` §5，不许对外宣称全自动）：
- U 核定长度不可算法复现（352 一致 / 103 上调 / 172 下调，下调占多数）→ 人工核定 + 留痕。
- 采购量不可算法复现（实测倍数 1.124/2.314/1.560/1.250，原表「加 30% 冗余」是假的）→ 需求可复现，采购人工核定。
- 模块列仅覆盖 570/5113 行（11.1%）→ 汇总必须标覆盖率、禁止外推。
- U 位重叠 13 对（含 4 对真撞车）→ 告警 + 人工裁决，不作硬约束。

## 4. 问题③：自动生成 —— 大部分能，边界量化

`domain/ports/generate.py` 开宗明义是「产品的主功能」，对应用户原话「自动化完成布线表」。链路：`Intent → to_flow_inputs → plan_flow → generate_links → 25 列布线表行`。

**能自动**：
- 意图 → 布线表行：交换机 → 服务器方向 **4562/5113 行（~89%）**规则生成；意图规则覆盖 **4430/4562 = 97.11%**。
- 线缆类型由两端端口速率派生 **99.71%**（≤1G→RJ45，双 100G→MPO，其余→LC-LC）。
- U 位标签（`40U`/`3-12U`/`31-32U`）、线长 N–T 列、耗材需求、标签、2D/3D 视图：全自动。
- 端口分配五规则 C1–C5（`端口号 = 组内位次 + base`，组内按机柜/U升序）：4562/4562。

**不能自动（诚实边界）**：
- 交换机互联（核心↔接入 100G MPO 上行、堆叠线，~551 行 13%）+ 特殊机型接线（144 行）：需 `ExplicitLink` 显式声明——「谁接谁」是拓扑设计决定，端口规律未破解，不假装能算。
- U 核定长度 / 采购量 / 模块列：人工（见 §3）。
- IP 段规划：当前不做。
- 机房平面图：是**输入**不是输出（物理 room 几何，人工给定）。

## 5. 建议方向与优先级

| 优先级 | 方向 | 理由 | 风险 |
| --- | --- | --- | --- |
| **P0（✅ 已实施）** | **网段级 IP 规划** | 真实表已有（V13/V9 11 行）；调研 `docs/research/04-commercial-products.md` P1-2 已识别「网段规划 + 使用率 + 冲突校验」是合理轻量能力（非 IPAM）；纯增量，不碰布线表生成与导出铁线 | 低 |
| P1 | 政务外网 / 冷通道第二套导入模板 | 扩大复用面；但几何层硬编码 403/404，需外置几何参数，改动大 | 中 |
| P2 | 耗材到货盘点 reconciliation | 需求清单 → 到货实物核对（箱号/数量/照片），衔接采购 | 中 |
| 不做 | 全自动交换机互联 | 13% 属拓扑设计决策，强行自动化会「假装能算」 | — |

**网段级 IP 规划设计要点**（P0）：
- 模型：`应用范围 → 地址段`（CIDR），登记交换机互联/服务器管理/业务/SDN/存储/带外/租户浮动等；轻量字段（用途、网段、掩码、备注），不做逐地址 IPAM。
- 能力：网段使用率统计 + 重叠/冲突校验 + 从 V13「IP地址段规划」sheet 导入 + 导出回写。
- 架构遵循引擎五规矩：`domain/` 零 IO、公式单点、适配器收口、`units.py` 常量中心、改生成逻辑必跑导出铁线（本特性纯增量，不触发）。

**落地结果**（P0 已实现并验收）：
- 后端：`domain/ipplan/segment.py`（纯函数：单 CIDR + 同前缀区间解析、容量、最小覆盖超网、重叠校验）→ `application/services/ipplan.py`（投影）→ `infrastructure/xlsx/ipplan_sheet.py`（按表头名读「IP地址段规划」+ 导出回写）→ `api/main.py` 新增 `GET /api/ipplan`、`GET /api/ipplan/export`。
- 前端：新增「IP 规划」页签（`#ipplan`，`views/IpPlanView.tsx`），统计卡 + 使用率条 + 网段明细 + 按用途汇总 + 冲突校验 + 导出 Excel。
- 真实 V13 实测：10 条登记网段 / 8 用途 / 206 子网 / **118,016** 规划地址；最小覆盖超网 `172.30.0.0/15`（131,072）；使用率 **90.04%**；**0 冲突**。使用率按「规划占用」口径披露，非实际分配率。
- 五验收全绿：pytest **1378 passed**（+50）、lint-imports **5 kept**、导出铁线 **123072 格 0 差异**（未触碰）、vitest **255 passed**、tsc **0 错**。

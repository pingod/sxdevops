# 巡检中心

巡检中心是任务工作台的第 4 个 Tab（`/tasks/workbench?taskTab=inspection`），覆盖主机、K8s 与中间件三类对象，并把「计划 → 执行 → 隐患闭环」串成一条链路。

```text
巡检计划（范围 + 巡检项 + 调度）
  → 巡检执行（逐目标只读采集，阈值判定级别）
  → 巡检结果（每目标 × 每巡检项：value / threshold / severity）
  → 隐患台账（跨次聚合：occurrences / first_seen_at / 状态）
  → AI 解读（结论、风险、建议；不改变判定）
```

## 数据模型

| 模型 | 职责 | 关键字段 |
| --- | --- | --- |
| `InspectionItem` | 巡检项目录 | `code`、`category`、`weight`、`threshold_config`、`remediation`、`is_enabled` |
| `InspectionPlan` | 巡检计划 | `scope`、`item_codes`、`schedule_type`、`next_run_at`、`ai_analysis_enabled` |
| `InspectionRun` | 一次巡检 | `status`、`score`、`*_count`、`scope_snapshot`、`item_codes`、`ai_*` |
| `InspectionResult` | 目标 × 巡检项 | `target_key`、`severity`、`value`、`threshold`、`evidence` |
| `InspectionIssue` | 隐患台账 | `dedupe_key`、`occurrences`、`status`、`first_seen_at`、`ai_advice` |

`threshold_config` 结构固定：

- 数值型 `{'warning': 80, 'critical': 90, 'unit': '%', 'comparison': 'gte'|'lte'}`
- 布尔型 `{'comparison': 'eq', 'expect': 'yes'}`
- 存在型 `{'comparison': 'flag'}`

判定只由 `evaluate_threshold` 完成；采集器不硬编码级别（离散状态如 `ready_replicas == 0` 例外，同时写 `value='0'/'1'` 供页面展示）。

## 内置巡检项（31）

- 主机 12：负载、CPU 空闲率、内存、Swap、磁盘、Inode、时钟同步、失败服务单元、待重启、SSH 失败登录、高危端口暴露、系统错误日志。
- K8s 7：节点就绪、节点资源压力、Pod 重启、异常 Pod、工作负载可用副本、集群容量水位、PVC 未绑定。
- 中间件 12：Redis（内存、命中率、复制、持久化、淘汰）、MySQL（连接、慢查询、主从、缓冲池）、ES（健康、未分配分片、堆使用率）。

新增巡检项只需在 `backend/ops/inspection_items.py` 增加一条定义 + 写对应采集逻辑，不需要改前端；阈值与权重在「巡检项」对话框内直接维护。

## 评分与隐患

- 扣分：`warning` 扣 `weight`，`critical` 扣 `weight × 2`，得分下限 0。
- 状态：有 `critical` → 存在严重问题；否则有 `warning` → 存在警告；否则正常；全部目标都失败 → 执行失败。
- 隐患去重键 `dedupe_key = {target_type}:{target_key}:{item_code}`：warning/critical 累加 `occurrences` 并刷新 `last_run`，`ok` 时把 `open/acknowledged` 置为 `resolved`；`ignored` 不自动变更；人工设置的 `status/owner` 与 `ai_advice` 不会被覆盖。

## 执行与调度

- 采集器 `ops/inspection_collectors.py`：主机走单次只读 SSH 脚本（`[sec:<code>]` 分节），K8s 走 `_get_k8s_client`，中间件复用 CMDB `ConfigItemPassword` 凭据。
- 目标解析：主机按 `TaskResource` + 数据范围；K8s 用 `rbac.k8s_access.k8s_scope`（只读，不要求执行权限）；中间件按 `visible_cmdb_resources`。
- 未选集群 / 未选中间件类型表示「不巡检该类」，不会把全平台资源拉进一次巡检。
- 首次执行写入 `scope_snapshot`，重跑直接用快照重建目标，不依赖计划是否仍存在。
- 调度：`python manage.py run_inspection_scheduler --interval 60 --limit 20`，Compose 里由 `inspection-scheduler` 服务常驻；调度触发时同步执行，避免调度进程退出时线程被杀。
- 执行超时（`running` 超过 1800s）在列表访问时自动标记失败。

## API

| 路径 | 说明 | 权限 |
| --- | --- | --- |
| `GET /api/inspections/overview/` | 今日巡检、未闭环隐患、7 日均分、趋势、Top 隐患 | `ops.inspection.view` |
| `GET/PATCH /api/inspections/items/` | 巡检项目录与阈值/权重维护 | `view` / `ops.inspection.manage` |
| `/api/inspections/plans/` | 计划 CRUD、`run_now`、`toggle_enabled`、`preview_next_runs` | `manage`（`run_now` 需 `execute`） |
| `/api/inspections/runs/` | 执行记录、`rerun`、`analyze`、`report` | `view`（`rerun` 需 `execute`，`analyze` 需 `analyze`） |
| `/api/inspections/issues/` | 隐患台账、`acknowledge`/`ignore`/`resolve` | `view` / `manage` |
| `POST /api/inspections/recommend-items/` | AI 推荐巡检项，模型不可用时回退全量启用项 | `ops.inspection.analyze` |

## AI 辅助

- 计划开启 `ai_analysis_enabled` 时，运行结束自动排队分析（`aiops.inspection.enqueue_run_analysis`），写回 `ai_status/ai_summary/ai_payload/ai_error`，**不改变 run 状态**。
- 未配置模型时 `POST /runs/{id}/analyze/` 返回 400 并提示先配置模型提供商。
- 智能助手新增问答类型 `inspection.analysis`（不需要知识环境），工具 `query_inspection_runs` / `query_inspection_issues`，Skill `sx-inspection-analysis`；提问「最近一次巡检发现了哪些严重问题」直接命中。

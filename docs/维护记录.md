# 维护记录

本文件按时间倒序记录每次**已发布的实质变更**：改了什么、为什么、涉及哪些迁移与环境变量、怎么验证、还有什么没做。它面向后续维护者，不是逐轮测试日记；单次排查过程留在 Issue，功能说明留在对应手册。

## 记录规范

新增一条记录时复制下面的骨架，放在「记录」小节最前面。

```markdown
## YYYY-MM-DD · vX.Y.Z · 一句话主题

- 提交：`<sha>`（标签 `vX.Y.Z`）
- 范围：<模块/文件面>
- 迁移：<迁移名或"无">
- 新增/变更环境变量：<变量或"无">
- 行为变更：<对使用者可见的变化，逐条>
- 验证：<实际跑过的命令与结果，包含未通过项>
- 遗留：<未做/受限项，没有就写"无">
```

硬性要求：

1. **同一次提交里更新**记录与对应功能手册，不做事后补记。
2. 验证只写真实执行过的命令与结果；没跑的写"未执行"，不推测。
3. 迁移、环境变量、默认值变化必须单独列出，升级的人只看这一节也能判断风险。
4. 密钥、真实主机、账号、Token、内网地址一律不写入本文件。

### 已知排字问题

`backend/sqlaudit/migrations/0004_encrypt_datasource_password.py` 的文件名与迁移依赖里是一串占位符，不是有意命名。**不要在后续版本直接改名或删除**：已经在 v2.0.3 上跑过迁移的环境会把它记进 `django_migrations`，改名会报缺失迁移并按新名字重跑 `RenameField` 而失败。要修正必须新增一个兼容迁移（记录旧名、改名、幂等跳过），并在升级说明里写清楚。

### 过程中的真实缺陷（已修，供后续参考）

| 缺陷 | 影响 | 修法 |
| --- | --- | --- |
| `Host.ssh_password` 加密后仍被当明文用 | 所有 SSH 任务认证失败 | 读取点统一 `decrypt_password` |
| `_capacity_request_lookup` 收到 `values('id')` 的 dict | 看板接口 500 | 兼容 dict/标量两种输入 |
| 终端 `RLIMIT_NPROC=128` 低于用户已有进程数 | `fork: Resource temporarily unavailable` | 去掉 NPROC 限制 |
| `start_new_session=True` 与子进程 `os.setsid()` 冲突 | `TIOCSCTTY` 失败，无控制终端 | 保留前导脚本 setsid，去掉 Popen 参数 |
| 聊天收尾 `.update()` 用终态过滤库中 running 行 | 永远匹配不到，任务卡在 running | 过滤条件改为 `status=running`+`claim_token` |
| 权限缓存 + `TestCase` 回滚 | 陈旧权限被复用，mock 进编码器后 OOM | 改信号失效 + 测试下关闭缓存 |

# 网络监控使用手册

网络监控模块基于 SNMP 对交换机、路由器、防火墙等网络设备进行纳管与持续采集，提供 NOC 运行态势、接口流量台账与设备健康趋势。模块代码位于 `backend/network/`，前端页面为「可观测性 → 网络监控 / 网络设备」。

## 架构

```
Vue 页面（/network/noc、/network/devices）
  → /api/network/*（Django DRF，RBAC + 审计）
  → PostgreSQL（设备/凭据/接口/指标样本）

network-poller 容器（独立进程，与主应用同镜像）
  → SNMP v2c/v3 GET/WALK → 网络设备
  → 系统健康（CPU/内存/温度）+ 接口计数器（64 位 HC 优先）
  → 速率差分（回绕补偿、重置识别）→ 指标样本入库
```

- 采集器是独立 Compose 服务 `network-poller`，运行 `python manage.py run_network_poller`，不占用 Web 进程资源。
- SNMP 凭据（Community、v3 认证/加密密钥）使用平台 Fernet 密钥（`CMDB_PASSWORD_ENCRYPTION_KEY`）加密落库，任何 API 不回显明文；编辑时留空表示保持原值。
- 设备在线状态翻转、接口中断/恢复会自动写入事件中心（module=`network`，category=`monitor`）；设备/凭据的增删改与测试、手动采集写入操作审计（category=`config`）。

## 权限

| 权限码 | 说明 |
| --- | --- |
| `network.device.view` | 查看设备、凭据摘要与接口台账 |
| `network.device.manage` | 纳管设备、维护凭据、测试连通性、手动采集 |
| `network.monitor.view` | 查看 NOC 总览与指标趋势 |

内置角色中，平台管理员与运维管理员拥有全部三项；研发工程师、审计员、只读访客拥有两项查看权限。

## 快速上手

1. 在「网络设备 → SNMP 凭据」新建凭据：v2c 填 Community；v3 填用户名、认证协议/密钥、加密协议/密钥（启用加密前必须先启用认证）。
2. 在「设备列表」纳管设备：名称、管理 IP、类型、厂商、凭据、端口（默认 161）。厂商选「其他」时首次采集会根据 sysDescr 自动识别（华为/H3C/思科/锐捷/中兴/Juniper/飞塔）。
3. 点「测试」验证连通性，点「采集」立即执行一轮完整采集；之后采集器按间隔自动轮询（系统默认 300 秒、接口默认 60 秒，均可按设备调整，下限 30 秒）。
4. 点「接口」打开抽屉查看接口台账、单接口流量趋势与设备健康趋势（近 1/6/24 小时、7 天）。
5. 「网络监控」页查看在线/离线统计、接口利用率 TOP 10、当前总流量与最近监控事件，每 30 秒自动刷新。

## 采集与指标口径

- 接口速率 = 计数器差分 × 8 / 时间窗口；64 位 HC 计数器优先，老设备回退 32 位。
- 计数器回绕按 2³²/2⁶⁴ 补偿；补偿后速率超过接口物理速率 2 倍判定为计数器重置，丢弃该样本。
- 设备重启（sysUpTime 回退）后首轮不计算速率，仅刷新快照。
- 利用率按接口速率（ifHighSpeed 优先，回退 ifSpeed）计算并封顶 100%。
- 健康指标：华为/H3C/思科/锐捷/中兴/Juniper/飞塔私有 OID（CPU/内存/温度，表取最大值）；无命中时回退 HOST-RESOURCES-MIB（hrProcessorLoad 平均、RAM 利用率）。
- 样本保留默认 30 天，采集器每小时清理一次；可用环境变量 `NETWORK_METRIC_RETENTION_DAYS` 调整。
- 指标查询自动降采样：≤2 小时原始点，≤48 小时分钟桶，更久小时桶（AVG 趋势 + MAX 尖峰）。

## 主要 API

| 端点 | 说明 |
| --- | --- |
| `GET /api/network/overview/` | NOC 总览（设备/接口统计、TOP 利用率、总流量、最近事件） |
| `GET/POST /api/network/devices/` | 设备列表（分页/筛选）与纳管 |
| `POST /api/network/devices/{id}/test/` | SNMP 连通性测试 |
| `POST /api/network/devices/{id}/poll/` | 立即采集一轮 |
| `GET /api/network/devices/{id}/interfaces/` | 设备接口台账 |
| `GET /api/network/devices/{id}/metrics/?hours=6` | 设备健康趋势 |
| `GET /api/network/interfaces/{id}/metrics/?hours=6` | 接口流量趋势 |
| `GET/POST /api/network/credentials/` | 凭据列表与创建（密钥只写不读） |

## 机房数字孪生

「数据中心 → 数字孪生」（`/datacenter/twin`，权限 `datacenter.twin.view`）把规划引擎的三维机房场景与 SNMP 实时状态叠加：

- 几何数据来自规划引擎 `GET /api/planning/api/scene`（毫米坐标，经 RBAC 反代），前端用 Three.js 渲染（`frontend/src/lib/twinScene.js`），机柜/设备全部 InstancedMesh，软渲染（SwiftShader）下亦可流畅运行。
- 实时状态来自 `GET /api/network/overview/` 与设备列表，每 30 秒刷新；纳管设备按名称/系统名与场景设备自动关联，离线设备与其所在机柜标红、高负载（利用率≥80%）标橙。
- 拖动旋转、滚轮缩放、点击机柜查看柜内设备；右侧栏列出纳管设备在线状态，点击可定位到关联机柜。
- 无 WebGL 的环境给出降级提示并引导至「IDC 上架布线」平面视图。
- 几何常量与公式镜像 `planning/web/src/domain/scene3d.ts`（引擎侧为几何真值唯一来源），改几何请改引擎，不要在渲染器另拍数字。

## 部署与验收

Compose 默认启用 `network-poller` 服务。本地开发可运行：

```bash
cd backend && python manage.py run_network_poller --once   # 采集一轮到期设备
cd backend && python manage.py test network                # 模块测试
```

无真实设备时可用 snmpsim 模拟验收：

```bash
pip install snmpsim pysmi cryptography
snmpsim-command-responder --data-dir=<数据目录> --agent-udpv4-endpoint=0.0.0.0:1161
# v3：追加 --v3-user=monitor --v3-auth-key=... --v3-auth-proto=SHA256 --v3-priv-key=... --v3-priv-proto=AES128
# 数据目录放 public.snmprec（v2c）；空上下文 v3 需要 self.snmprec
```

注意：snmpsim 的 .snmprec 必须按 OID 数值排序，否则子树 WALK 会漏数据；v3 空上下文请求依赖 `self.snmprec` 文件。
